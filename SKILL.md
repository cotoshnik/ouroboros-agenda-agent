# Автономный агент подготовки аналитических справок и презентаций

Навык автоматизирует ежедневную подготовку аналитических материалов дежурной
смены: приём фактических показателей из внутренних источников, контроль
полноты данных, отбор актуальных показателей и сборку итоговых материалов —
аналитической справки (Word) и презентации (PPTX по шаблону пользователя).
Финальная верификация и интерпретация остаются за аналитиком
(human-in-the-loop).

**Навык НЕ использует новости, RSS, публикации и веб-сигналы.** Единственные
источники значений: карта показателей `memory/knowledge/indicators.json` и
фактические observations, загруженные через `save_observation`.

## 1. AS IS — текущий процесс (вход → шаги → выход)

**Входной контракт:** тема/перечень тем справки, приоритетные направления,
срок подготовки, требуемый формат выходного документа.

**Граф ручных операций (time-per-step, суммарно 135–200 мин на справку):**

| # | Шаг | Исполнитель | Время, мин |
|---|-----|-------------|-----------:|
| 1 | Получение задачи / актуализация темы | аналитик | 5–10 |
| 2 | Ручной мониторинг источников (почта, инфопанели) | аналитик | 30–45 |
| 3 | Отбор релевантных значений и сигналов | аналитик | 20–30 |
| 4 | Извлечение фактов, цифр, показателей | аналитик | 25–40 |
| 5 | Сверка данных между источниками | аналитик | 15–25 |
| 6 | Формирование структуры справки | аналитик | 15–20 |
| 7 | Подготовка текста, компоновка справки и презентации | аналитик | 20–25 |
| 8 | Ручная корректировка при смене повестки | аналитик | 5–15 |

**Выходной артефакт:** аналитическая справка / презентация для штаба.

**Болевые точки:** 10–18 человеко-часов рутинной нагрузки в день на команду;
ручная навигация по источникам; повторяемость действий; человеческий фактор
при сверке и переносе значений в документы.

## 2. Данные навыка — карта показателей

Агент оперирует картой из **67 показателей**
(`memory/knowledge/indicators.json`, источник —
`Показатели_для_подготовки_материалов.xlsx`):

- **Базовый блок (49 показателей)** — обязателен в каждой справке:
  клиентопоток и его динамика/прогноз, остаток наличности, выдача в УС,
  КТД, инциденты безопасности (в т.ч. социнженерия), инциденты СВО
  (окно 09:00→09:00), IT-инциденты (окно 07:00→07:00), инциденты
  кибербезопасности и DDoS, заболеваемость, природные и технологические
  инциденты.
- **Динамический блок (18 показателей)** — включается при наличии
  фактических данных: прогноз пиковых дней, взносы/выдача/сальдо ВСП
  (RUB/EUR/USD), средние значения с начала года и пр.

**Правила отсечки и критерии отбора** (за какие сутки берётся значение,
во сколько приходит письмо-источник) хранятся в поле `selection_criterion`
каждого показателя и сведены в `memory/knowledge/sources.md`. Значение вне
допустимого окна не считается актуальным.

## 3. TO BE — целевой пайплайн

```
внутренние источники (письма, инфопанели)
        │
        ▼
[1] collect   — save_observation: фактические значения за дату (collector_agent)
        │
        ▼
[2] validate  — check_completeness: полнота базового блока,
                сверка окон отсечки с критериями отбора
        │
        ▼
[3] select    — analyst_agent: detect_hot_topics + select_presentation_indicators:
                выбор актуальных показателей для презентации, каждое решение
                с обоснованием; сервер повторно валидирует выбранные ID
        │
        ▼
[4] export    — editor_agent: export_report → DOCX (полная сводка)
                + PPTX (по шаблону пользователя, только проверенные показатели)
        │
        ▼
[5] review    — HUMAN-IN-THE-LOOP: верификация, правки, интерпретация
        │
        ▼
итоговые материалы: справка .docx + презентация .pptx
```

Оркестрация — по протоколу A2A между тремя специализированными агентами
(см. `agents/`): Collector → Analyst → Editor.

### MCP-инструменты (сервер `mcp/server.py`, порт 9999)

| Инструмент | Назначение |
|------------|-----------|
| `list_indicators` | карта показателей, фильтр по блоку (base/dynamic/all) |
| `get_selection_criteria` | критерии отбора и окна отсечки по источникам |
| `save_observation` | сохранить фактическое значение показателя за дату |
| `get_observations` | получить собранные значения за дату |
| `check_completeness` | каких базовых показателей не хватает за дату |
| `detect_hot_topics` | показатели, сработавшие по пороговым правилам HOT_RULES |
| `select_presentation_indicators` | отбор для презентации: вход для аналитика + серверная валидация selections |
| `build_report_draft` | полная сводка в markdown (базовый + динамический блоки, сигналы, полнота) |
| `inspect_pptx_template` | анализ PPTX-шаблона: макеты, плейсхолдеры, тема |
| `export_report_docx` | справка в Word (.docx + .md) с валидацией |
| `export_report_pptx` | презентация по предоставленному шаблону (.pptx) с валидацией |
| `export_report` | финальный контракт цикла: DOCX + PPTX, success только при обоих валидных файлах |

## 4. Политика автономии

| Зона | Режим |
|------|-------|
| Приём значений показателей из источников | **авто** |
| Контроль полноты и сверка окон отсечки | **авто** |
| Отбор показателей для презентации | **analyst_agent** с обоснованиями; сервер валидирует ID и принудительно включает HOT_RULES |
| Генерация DOCX/PPTX | **авто** |
| Публикация/рассылка итоговых материалов | **human-in-the-loop** — запрещено без явного подтверждения аналитика |
| Любые внешние/сетевые данные | **не используются вообще** |

Ограничения: агент не интерпретирует показатели и не формулирует выводы и
рекомендации — это зона ответственности аналитика; агент не изменяет
карту показателей, шаблон справки, PPTX-шаблон и пороговые правила без
ревью человека (см. `safety/`); агент не подменяет отсутствующие значения
и не выдаёт оценки модели за фактические показатели.

## 5. Целевые метрики навыка (для замера AS IS → TO BE)

- время подготовки типовой справки: −50–70%;
- рутинная нагрузка команды: с 10–18 до 4–8 человеко-часов в день;
- доля автоматически собранных материалов в итоговых документах: 70–85%;
- точность и релевантность материалов: ≥ 70% по экспертной оценке.

## 6. Критерий завершения задачи (контракт результата)

Задача навыка — **собрать аналитическую справку и презентацию**. Цикл
считается выполненным, только когда выполнены ВСЕ условия:

1. Внутренние показатели загружены через `save_observation`;
   полнота проверена `check_completeness`.
2. Отбор показателей для презентации выполнен с обоснованиями
   (`select_presentation_indicators`) и прошёл серверную валидацию;
   решения записаны в audit-артефакт цикла (`data/audit_<дата>.json`).
3. `export_report` вернул `status: success` — то есть созданы и прошли
   валидацию ОБА файла: `data/report_draft_<дата>.docx` и
   `data/report_draft_<дата>.pptx` (последний — по шаблону пользователя).
   Если создан один файл, а второй нет — статус не success, этап ошибки
   указан в `failed_stage`, успешный артефакт не удаляется.
4. Оба материала переданы аналитику на верификацию (human-in-the-loop).
   Автоматическая отправка и публикация запрещены (BIBLE.md, P1).

Правила вызова инструментов:

- Инструменты вызываются ТОЛЬКО через подключённый MCP-сервер
  (Settings → Advanced → MCP; сервер запущен: `python3 mcp/server.py`,
  на Windows: `py mcp\server.py`).
- ЗАПРЕЩЕНО импортировать модули `mcp/` или выполнять python-скрипты
  вместо MCP-вызовов. Если выполнение команд заблокировано средой —
  агент просит человека запустить сервер, а не обходит ограничение
  ручным конструированием данных.
- Модель не изменяет значения, единицы, даты и источники показателей и
  не экспортирует непроверенные сервером ID.
