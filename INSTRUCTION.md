# ИНСТРУКЦИЯ: запуск и работа с агентом подготовки справок и презентаций

Версия 3 (production-контур). Проект Sber AI Hack — автономный агент на
базе Ouroboros. Документ описывает всё: от установки до ежедневной работы,
включая данные MCP-сервера, все инструменты, форматы файлов и типичные
проблемы.

---

## 1. Что это такое

Агент `agenda_briefing_agent` автоматизирует ежедневную подготовку
аналитических материалов дежурной смены:

1. **Принимает фактические показатели** (67 показателей карты данных:
   клиентопоток, наличность, КТД, инциденты и т.д.) из внутренних
   источников — через инструмент `save_observation`.
2. **Контролирует полноту** обязательного базового блока (49 показателей)
   и применяет пороговые правила (`HOT_RULES`).
3. **Отбирает актуальные показатели для презентации** — analyst_agent
   с обоснованием каждого решения; сервер повторно валидирует выбор.
4. **Собирает два итоговых файла**: справку в Word (полная сводка) и
   презентацию PPTX — строго по шаблону, предоставленному пользователем.
5. Финальную верификацию, выводы и отправку делает **человек-аналитик**
   (human-in-the-loop). Агент ничего никуда не отправляет сам.

**Агент НЕ использует новости, RSS, сайты и веб-сигналы.** Единственные
источники значений — карта показателей и фактические observations.
Тестовых/демонстрационных данных в проекте нет: отсутствующее значение
честно помечается «— нет данных —».

| Компонент | Требование |
|-----------|-----------|
| ОС | macOS 12+ / Windows / Linux |


```cmd

```

(если `py` не найден — `python mcp\server.py`)

Ожидаемый вывод:


**Окно терминала не закрывайте** — сервер живёт, пока работает процесс.

```bash
nohup python3 mcp/server.py > /dev/null 2>&1 &
```

## 6. Подключение сервера в Ouroboros

Путь в интерфейсе: **Settings → Advanced → MCP** → добавить сервер.

| Поле | Значение |
|------|----------|
| **Server ID / Name** | `agenda_briefing` |
| **Display name** | `Аналитические справки (локально)` — любая подпись |
| **Server URL** | `http://localhost:9999/mcp` |
| **Transport** | `streamable_http` |
| **Allowed tools** | пусто (= все) или перечислить 12: `list_indicators, get_selection_criteria, save_observation, get_observations, check_completeness, detect_hot_topics, select_presentation_indicators, build_report_draft, inspect_pptx_template, export_report_docx, export_report_pptx, export_report` |

Либо вставьте готовый JSON из файла `mcp/mcp_servers.json`:

```json
{
  "name": "agenda_briefing",
  "url": "http://localhost:9999/mcp",
  "transport": "streamable_http"
}
```

После сохранения Ouroboros **сам обнаружит инструменты** сервера.
Проверка: спросите агента «какие MCP-инструменты тебе доступны?» —
должен перечислить 12 штук.

> **Важно:** агент вызывает инструменты только через это MCP-подключение.
> Если агент вместо MCP-вызовов пытается запускать python-скрипты или
> импортировать `mcp/server.py` — значит, сервер не запущен или
> подключение не настроено. Запустите сервер (раздел 5) и скажите агенту:
> «используй только MCP-инструменты сервера agenda_briefing».

## 7. Данные MCP-сервера — полное описание

### 7.1. Карта показателей — `memory/knowledge/indicators.json`

Единый источник истины по показателям. 67 записей:

```json
{
  "id": 26,
  "name": "Коэффициент технической доступности, %",
  "base_block": true,
  "dynamic_block": false,
  "selection_criterion": "Значение КТД берется за прошедшие сутки (письмо ... в 07:00-07:30)"
}
```

- `base_block: true` — показатель **обязателен** в каждой справке (49 шт.);
- `dynamic_block: true` — включается **при наличии фактических данных** (18 шт.);
- `selection_criterion` — окно отсечки и источник. Значение вне окна
  не считается актуальным.

### 7.2. Фактические показатели — `data/observations_<дата>.json`

Значения за конкретные сутки. Создаётся инструментом `save_observation`:

```json
{
  "date": "2026-10-26",
  "observations": [
    {
      "indicator_id": 26,
      "name": "Коэффициент технической доступности, %",
      "block": "base",
      "value": 99.42,
      "unit": "%",
      "source": "письмо 07:00-07:30",
      "collected_at": "2026-10-26T07:31:12"
    }
  ]
}
```

Повторное сохранение по тому же `indicator_id` **перезаписывает** значение
(актуализация в течение дня). Запись атомарна (временный файл + замена),
конкурентные сохранения сериализуются блокировкой — обновления не теряются.
Повреждённый файл не перезаписывается молча: инструменты вернут ошибку —
восстановите файл или переместите его в архив.

### 7.3. Решения отбора — `data/audit_<дата>.json`

Каждое решение analyst_agent (и серверная валидация) фиксируется:

```json
{
  "date": "2026-10-26",
  "source": "analyst",
  "decisions": [
    {"indicator_id": 26, "priority": "high", "include": true,
     "justification": "сработало пороговое правило: КТД ниже 99.5%",
     "ref": "hot_rule"},
    {"indicator_id": 1, "priority": "normal", "include": true,
     "justification": "ежедневный контроль клиентопотока",
     "ref": "observation"}
  ],
  "warnings": []
}
```

### 7.4. Итоговые материалы

- `data/report_draft_<дата>.docx` — справка в Word: базовый блок целиком
  (с «— нет данных —» для отсутствующих), динамический блок по факту,
  сигналы, полнота. Всегда помечена «ЧЕРНОВИК».
- `data/report_draft_<дата>.pptx` — презентация по вашему шаблону:
  титульный слайд, один слайд на отобранный показатель (название,
  значение, единица, дата, источник, обоснование), финальный слайд
  «Полнота данных». Мастер, макеты, тема, логотипы шаблона сохраняются.
- Оба файла пишутся атомарно и валидируются (ZIP/OOXML, открытие,
  наличие слайдов) до возврата успеха.

## 8. Все 12 инструментов — параметры и примеры

Прямой вызов (для тестов без Ouroboros):

```bash
curl -X POST http://localhost:9999/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"<ИМЯ>","arguments":{<АРГУМЕНТЫ>}}}'
```

В чате Ouroboros достаточно сказать по-человечески (примеры фраз ниже).

### 8.1. `list_indicators` — карта показателей

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `block` | string | нет | `base` / `dynamic` / `all` (по умолч. `all`) |

Фраза агенту: «Покажи показатели базового блока».

### 8.2. `get_selection_criteria` — окна отсечки

Без параметров. 53 показателя с критериями (за какие сутки, когда письмо).
Фраза: «Когда приходят данные по IT-инцидентам?»

### 8.3. `save_observation` — загрузить фактическое значение

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `indicator_id` | int | да | id из карты (1–68) |
| `date` | string | да | `ГГГГ-ММ-ДД`, реальная календарная дата |
| `value` | number/string | да | значение (строки до 500 символов) |
| `unit` | string | нет | единица («млрд руб.», «%», «шт.») |
| `source` | string | нет | источник («письмо 06:30») |

Фраза: «Запиши: КТД за сегодня 99.87%, источник — письмо 07:15».

### 8.4. `get_observations` — что собрано за дату

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |

Фраза: «Что уже собрано за сегодня?»

### 8.5. `check_completeness` — полнота базового блока

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |

Фраза: «Все ли базовые показатели собраны?»

### 8.6. `detect_hot_topics` — сработавшие пороги

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |

Проверяет фактические значения по правилам `HOT_RULES` (КТД < 99.5%,
значимые инциденты, критичные IT, DDoS, план «Ковёр» и др.).
Фраза: «Есть ли горячие показатели за сегодня?»

### 8.7. `select_presentation_indicators` — отбор для презентации

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `date` | string | да | |
| `selections` | array | нет | решения аналитика-агента (см. ниже) |

Два режима:

- **Без `selections`**: возвращает вход для анализа (показатели с
  фактическими значениями, полнота, HOT_RULES) и серверное предложение
  (включаются только сработавшие пороги).
- **С `selections`**: серверная валидация отбора. Каждое решение:
  ```json
  {"indicator_id": 1, "priority": "normal", "include": true,
   "justification": "ежедневный контроль клиентопотока", "ref": "observation"}
  ```
  Сервер отклоняет id без фактического наблюдения за дату, чинит
  недопустимые приоритеты и **принудительно включает** показатели
  HOT_RULES. Результат записывается в `data/audit_<дата>.json`.

Фраза: «Выбери актуальные показатели для презентации и обоснуй».

### 8.8. `build_report_draft` — полная сводка (markdown)

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |

4 раздела: базовый блок → динамический → сигналы → полнота.
Фраза: «Собери черновик справки за сегодня».

### 8.9. `inspect_pptx_template` — анализ шаблона

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `template_path` | string | нет* | *обязателен, если не задан `AGENDA_PPTX_TEMPLATE` |

Возвращает макеты, плейсхолдеры, число слайдов, тему (шрифты, цвета),
размеры. **Вызывайте перед первым экспортом** с новым шаблоном.

### 8.10. `export_report_docx` — справка в Word

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |

Сохраняет `data/report_draft_<дата>.docx` (+ `.md`), валидирует файл.

### 8.11. `export_report_pptx` — презентация по шаблону

| Параметр | Тип | Обяз. | Описание |
|----------|-----|-------|----------|
| `date` | string | да | |
| `template_path` | string | нет* | *или `AGENDA_PPTX_TEMPLATE` |
| `selection` | array | нет | провалидированный отбор; без него — audit цикла, затем серверное предложение |

Без шаблона возвращает `status: template_required` (успех не имитируется).

### 8.12. `export_report` — ФИНАЛЬНЫЙ КОНТРАКТ ЦИКЛА

| Параметр | Тип | Обяз. |
|----------|-----|-------|
| `date` | string | да |
| `template_path` | string | нет* |
| `selection` | array | нет |

Создаёт и валидирует ОБА файла. Ответ:

```json
{
  "date": "2026-10-26",
  "status": "success",
  "docx_path": "data/report_draft_2026-10-26.docx",
  "pptx_path": "data/report_draft_2026-10-26.pptx",
  "selected_indicator_ids": [1, 26],
  "missing_base_count": 0,
  "warnings": []
}
```

Если один файл не создан/не валиден: `status: "error"`, `failed_stage`
(`docx`/`pptx`), успешный артефакт **не удаляется**.
Фраза: «Собери справку и презентацию за сегодня».

## 9. Ежедневный рабочий цикл (runbook)

Тайминг — по расписанию источников (`memory/knowledge/sources.md`).

```
06:10  письмо по кибербезопасности        08:00  инциденты безопасности
06:30  письмо по наличности/УС/ВСП        09:00  сводка СВО
07:05  IT-инциденты                       09:05  ДЕДЛАЙН полноты (Штаб)
07:30  КТД
```

### Сценарий с агентом (чат Ouroboros)

1. **Запустите сервер** (раздел 5) — один раз утром.
2. По мере прихода писем: «Запиши остаток наличности 512.3 млрд руб.,
   источник письмо 06:30» → `save_observation`.
3. «Проверь полноту» → `check_completeness`. Пропуски — запросить
   источник или принять пометки «— нет данных —».
4. «Есть ли сработавшие пороги?» → `detect_hot_topics`.
5. «Выбери актуальные показатели для презентации» →
   `select_presentation_indicators` (проверьте обоснования в
   `data/audit_<дата>.json`).
6. «Собери справку и презентацию» → `export_report`.
   **Цикл завершён только при `status: success`** (оба файла валидны).
7. **Аналитик**: открывает .docx и .pptx, проверяет цифры, добавляет
   выводы, снимает пометку «ЧЕРНОВИК», утверждает и отправляет.
   Без этого шага материалы никуда не уходят (BIBLE.md, P1).


В чате агента:

1. Загрузите несколько реальных значений: «Запиши КТД 99.42%…» и т.д.
2. «Выбери актуальные показатели для презентации» — агент обоснует отбор,
   сервер провалидирует.
3. «Собери справку и презентацию за сегодня, шаблон
   templates/report_template.pptx» — готовые DOCX и PPTX за секунды.

Что показать жюри:

- AS IS: 135–200 минут ручной работы → TO BE: один цикл MCP-вызовов
  и два готовых документа.
- Отбор с обоснованиями и серверной валидацией — модель не может
  «протащить» непроверенный показатель.
- PPTX собран по фирменному шаблону: мастер, тема, логотип сохранены.
- Пометка «ЧЕРНОВИК» и human-in-the-loop — безопасность по BIBLE.md.

## 11. Типичные проблемы и решения

| Симптом | Причина | Решение |
|---------|---------|---------|
| `Address already in use` | порт занят | `pkill -f "mcp/server.py"` или `AGENDA_PORT=9998 python3 mcp/server.py` (и URL в конфиге Ouroboros) |
| Ouroboros не видит инструменты | сервер не запущен / неверный URL | `curl http://localhost:9999/health`; URL = `http://localhost:9999/mcp` |
| `ModuleNotFoundError: pptx` | не установлена зависимость | `pip install -r requirements.txt` |
| `status: template_required` | не передан шаблон | `template_path` в вызове или `AGENDA_PPTX_TEMPLATE` |
| `PPTX-шаблон повреждён / не открывается` | битый или не-PPTX файл | проверьте файл: открывается ли в PowerPoint; передайте корректный .pptx |
| `в шаблоне нет макета с плейсхолдером заголовка` | шаблон без подходящих макетов | добавьте в шаблон макет с плейсхолдерами заголовка и текста |
| «— нет данных —» в справке | показатель не загружен | загрузить через `save_observation` или оставить пометку (честнее, чем выдуманное значение — BIBLE.md P2) |
| `файл observations ... повреждён` | невалидный JSON | восстановить из бэкапа/git или переместить в архив; сервер молча не перезаписывает |
| `date должен быть в формате ГГГГ-ММ-ДД` | неверный формат | только `2026-10-26`, не `26.10.2026` |
| `не является реальной календарной датой` | например 2026-02-30 | валидная дата |
| `показатель с id=N не найден` | нет такого id | допустимые id — из `list_indicators` |
| Агент запускает python-скрипты вместо MCP-вызовов | сервер не запущен / нет подключения | запустить сервер, проверить подключение, сказать агенту: «используй только MCP-инструменты agenda_briefing» |
| `SAFETY_VIOLATION ... Reasoning is mandatory for this endpoint` | ошибка провайдера модели при проверке команд в Ouroboros — **не сбой проекта** | работать через MCP-подключение; при полной блокировке — сменить модель/провайдера в Settings → Models |
| Агент написал значения «от себя» | нарушение BIBLE.md P2 | отклонить результат; потребовать пометку «— нет данных —» и реальную загрузку |
| Skill review quorum failure | одна ревью-модель | добавить ключ второго провайдера (гайд, раздел 11) |

## 12. Кастомизация (что и где менять)

| Задача | Где менять | Ограничение |
|--------|-----------|-------------|
| Пороги «горячих» тем | `mcp/server.py` → `HOT_RULES` | **только через ревью** (BIBLE.md P4) |
| Карта показателей | `memory/knowledge/indicators.json` | **только через ревью** (P4) |
| Шаблон справки | `memory/knowledge/report_template.md` + `build_report_draft` | **только через ревью** (P4) |
| PPTX-шаблон | ваш `.pptx` + `template_path` / `AGENDA_PPTX_TEMPLATE` | свободно; анализ — `inspect_pptx_template` |
| Порт/хост/каталог данных | переменные окружения (раздел 5) | свободно |

После правок `mcp/*.py` — перезапустить сервер.

Тесты после любых изменений:

```bash
python3 -m unittest discover -s tests -v
```

## 13. Безопасность (коротко, полное — `safety/BIBLE.md`)

1. Агент **не отправляет** материалы — только человек (P1).
2. Агент **не выдумывает** значения и не конструирует данные вручную:
   нет данных = пометка (P2).
3. Каждое изменение кода/правил — через ревью, откат через git (P3).
4. Неприкосновенны: `BIBLE.md`, карта показателей, шаблон справки,
   пороговые правила, любые ключи/токены (P4).
5. Каждое автономное решение логируется: scratchpad + audit-артефакт (P5).
6. Сеть — только localhost; внешних запросов нет (P6).
7. Режим `/evolve` запрещён; `/panic` доступен аналитику всегда (P7).
