# Протокол A2A: взаимодействие агентов (п. 9.3 гайда Ouroboros)

Процесс подготовки справки и презентации разделён между тремя
специализированными агентами. Каждый — отдельный контур со своей ролью,
политикой автономии и набором MCP-инструментов (карточки: `*.agent.json`).

Данные — только фактические показатели из внутренних источников.
Новости, RSS и веб-сигналы не используются нигде в пайплайне.

## Схема взаимодействия

```
        внутренние источники (письма 06:10–08:00, инфопанель, сводки)
                    │
                    ▼
        ┌───────────────────────┐
        │   collector_agent     │  auto
        │  приём показателей,   │
        │  окна отсечки         │
        └───────────┬───────────┘
                    │ A2A handoff: наблюдения за сутки + отчёт о полноте
                    ▼
        ┌───────────────────────┐
        │    analyst_agent      │  auto, обоснования → audit-артефакт
        │ HOT_RULES + отбор     │
        │ актуальных показателей│
        └───────────┬───────────┘
                    │ A2A handoff: провалидированный отбор (selected_indicator_ids)
                    ▼
        ┌───────────────────────┐
        │    editor_agent       │  auto для генерации файлов
        │  DOCX (полная сводка) │
        │  + PPTX (по шаблону)  │
        └───────────┬───────────┘
                    │ A2A handoff: оба файла валидны (status=success)
                    ▼
        ┌───────────────────────┐
        │   АНАЛИТИК (человек)  │  human-in-the-loop
        │ верификация, выводы,  │
        │ утверждение и отправка│
        └───────────────────────┘
```

## Контракт handoff (сообщение между агентами)

```json
{
  "protocol": "A2A",
  "from": "analyst_agent",
  "to": "editor_agent",
  "task_id": "briefing-2026-10-26",
  "payload": {
    "date": "2026-10-26",
    "completeness": {"complete": false, "missing_base_count": 47},
    "selected_indicator_ids": [1, 26],
    "audit_ref": "data/audit_2026-10-26.json",
    "template_path": "templates/report_template.pptx"
  },
  "requires_confirmation": false
}
```

Правила:

1. Каждый handoff ссылается на `task_id` вида `briefing-<дата>` — сквозной
   идентификатор цикла (пишется в scratchpad и audit).
2. Сообщение `requires_confirmation: true` — обязательное подтверждение
   аналитиком до продолжения (отправка материалов, смена шаблона).
3. Деградация: если к 09:05 базовый блок не полон, collector всё равно
   делает handoff со списком недостающих — в справке они помечаются
   «— нет данных —», в презентацию не выносятся; аналитик решает,
   ждать ли источник.
4. Общего состояния у агентов нет: состояние — только в файлах `data/`,
   все обращения — через MCP-инструменты. Отбор показателей передаётся
   только типизированным JSON-контрактом, произвольный текст модели в
   PPTX-генератор не передаётся.
